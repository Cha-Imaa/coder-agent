The outer loop

Plan, do the work, run the tests, and retry with what went wrong.

Slow: one lap per tryThe tests decide when it is done, not the model

It stops when

  • the tests pass → passed
  • all four tries are used → failed
  • the step budget runs out → gave up

Retrieval

RAG: understanding the repository

Index the code once, then retrieve the most relevant chunks for each task.

Hybrid retrievalKeywords and meaning, fused by rank

Indexing

  1. Repo filesloader + ignore rules
  2. Code chunkstree-sitter, line-window fallback
  3. Chromalocal embeddings + metadata

Retrieval

  1. BM25 + densekeywords + semantic similarity
  2. Reciprocal rank fusioncombine the ranked lists
  3. Top 6 chunksup to 6,000 characters to plan + act

Defaults: ≤ 1,500 characters per chunk · 60-line fallback window · 10-line overlap · 384-D embeddings

State

Context and persistent memory

What the model sees on each call, and what a run can resume from.

Token budgetSummarise once history passes 60k tokens

Conversation history

Requests, tool calls and tool results build up in LangGraph state. The Act model sees the managed history on every call.

Context management

The six most recent tool outputs stay intact; older long ones are trimmed, and past 60k tokens the history is summarised.

SQLite checkpoints

Graph state is stored by thread, so a run can pause, resume, and span several turns.

Context management controls what the model sees; checkpoints control what the workflow can resume.

Looking back

Lessons learned, and next steps

A working, measurable agent loop, and where to take it next.

  1. Retrieval is situational

    On small repositories, exploring with tools can be enough.

    Adaptive RAG by task and repository size

  2. Tool loops drive cost

    ~99% of measured tokens were spent in Act.

    Better context selection, reusable summaries

  3. Tests are necessary, not sufficient

    Visible tests can pass while hidden requirements fail.

    Stronger regression tests and verification

  4. Production needs stronger boundaries

    Local-first is not multi-tenant infrastructure.

    Isolated workspaces, queues, shared persistence
