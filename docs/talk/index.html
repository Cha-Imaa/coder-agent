Two loops drive the agent · 1 of 2

The outer loop

Plan, do the work, run the tests, and retry with what went wrong.

It stops when

  • the tests pass → passed
  • all four tries are used → failed
  • the step budget runs out → gave up

Two loops drive the agent · 2 of 2

The inner loop

Ask for a tool, run it, look at the result, repeat. This is step 2 of the outer loop.

It stops when

  • no more tool requests → the tests run
  • 40 Act steps are used → gave up

Tools

MCP: giving the model actions

A real Model Context Protocol client and server, talking over stdio.

  1. the model chooses a tool
  2. MCP client stdio
  3. local MCP server
read_fileread a file's contents
edit_filechange part of a file
write_filecreate or overwrite a file
list_dirlist a directory
search_codesearch the repository
run_commandrun a shell command

Typical sequence: search_code → read_file → edit_file → run_command → result back to the model

Retrieval

RAG: understanding the repository

Index the code once, then retrieve the most relevant chunks for each task.

Indexing

  1. Repo filesloader + ignore rules
  2. Code chunkstree-sitter, line-window fallback
  3. Chromalocal embeddings + metadata

Retrieval

  1. BM25 + densekeywords + semantic similarity
  2. Reciprocal rank fusioncombine the ranked lists
  3. Top 6 chunksup to 6,000 characters to plan + act

Defaults: ≤ 1,500 characters per chunk · 60-line fallback window · 10-line overlap · 384-D embeddings
